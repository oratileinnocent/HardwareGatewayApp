1. INTRODUCTION

In modern IT administration, remote troubleshooting, and digital workflow management, seamless cross-device control is essential. However, traditional software-based remote desktop solutions (such as TeamViewer, AnyDesk, and Windows RDP) present significant operational constraints. They mandate pre-installed agent software, elevated host administrative permissions, persistent internet access, and unrestricted firewall permissions. In high-security, air-gapped, or restricted environments, installing external client software is frequently blocked by host security policies.

This project addresses these gaps by proposing a Hardware-Level USB Remote Access Gateway powered by an ESP32-S3 microcontroller. By emulating native USB Human Interface Device (HID) protocols directly at the hardware layer, the target computer recognizes the gateway as a standard, driverless physical keyboard and mouse. A mobile smartphone connects wirelessly to the gateway's embedded WebSocket server, transmitting real-time touch vectors and keystrokes. This project is worth solving as it creates an agentless, zero-configuration remote access bridge that operates independently of the target host's operating system, software permissions, or network firewalls.

2. PROJECT OBJECTIVES

The primary objective of this project is to design, construct, and evaluate a zero-driver hardware gateway that translates wireless mobile inputs into native USB HID events. Specific implementation objectives include:

  • Hardware HID Emulation: Configure the ESP32-S3 USB OTG peripheral to natively register as a combined USB Keyboard and Mouse device on Windows, Linux, and macOS.
  • Low-Latency Wireless Streaming: Implement an embedded C++ WebSocket server on the ESP32-S3 delivering sub-30ms round-trip latency for real-time touch vector transmission.
  • Mobile Control Web Application: Develop a responsive HTML5 touch interface (hosted directly from SPIFFS/LittleFS flash memory) featuring a touchpad area, multi-touch scroll, right-click actions, and a virtual keyboard.
  • Macro Execution Engine: Implement one-tap shortcut execution for complex keystroke sequences (e.g., Win+R, terminal scripts, system control shortcuts).
  • Hardware Security Integration: Incorporate a physical GPIO kill-switch and status LED indicators to instantly drop wireless broadcasting at the hardware layer when activated.

3. PROJECT DESCRIPTION

The proposed system consists of an embedded hardware dongle that bridges a smartphone and a host computer. Upon insertion into a host USB port, the target machine automatically enumerates the device as a standard USB human input device without requiring driver installations or administrative rights.

Target Market: The system is designed as an independent prototype with applications for IT support engineers, system administrators managing headless or air-gapped computers, network technicians performing field maintenance, and accessibility users requiring mobile-driven PC control.

Scope & Features: The project covers physical USB HID signal injection, local peer-to-peer Wi-Fi (SoftAP) hosting, real-time touch vector parsing, and physical security cutoff mechanisms. Out of scope for this initial phase are video feed capture (video streaming back to the phone) and Bluetooth Classic audio passthrough, maintaining a strict focus on low-latency input control and high reliability.

4. PROJECT TECHNOLOGY

The hardware and software technologies selected for design and implementation include:

  • ESP32-S3 Microcontroller: Dual-core Xtensa LX7 processor with native USB OTG hardware support required for USB HID stack emulation.
  • Firmware Framework: C++ utilizing the Arduino ESP32 core and Adafruit_TinyUSB / USBHID libraries for native descriptor configuration.
  • Communication Protocol: Asynchronous WebSockets over HTTP (ESPAsyncWebServer) operating over a 2.4 GHz SoftAP Wi-Fi network.
  • Mobile UI: Lightweight HTML5, CSS3, and JavaScript touch-event handling library compiled into flash storage using SPIFFS/LittleFS filesystem.
  • Hardware Peripherals: Physical tactile pushbuttons for hardware RF disablement and dual-color status LEDs (Wi-Fi activity and HID bus state).

1. INTRODUCTION

Primary Intent & Engineering Purpose: This technical design documentation defines the architectural blueprints, firmware decomposition, electrical interconnects, and protocol workflows for the Hardware-Level USB Remote Access Gateway via ESP32-S3 HID Emulation. Developed as the principal technical deliverable for Project Design III (PJD 301B), this document specifies the engineering mechanisms necessary to construct a working physical prototype capable of bridging a handheld mobile touch interface to an air-gapped target PC as a native, driverless USB peripheral.

System Demarcation & Technical Scope: The engineering scope centers on the implementation of the Espressif ESP32-S3 dual-core microcontroller, leveraging its on-die Full-Speed USB OTG physical transceiver for direct differential signaling (D+/D-) on GPIO pins 19 and 20. The firmware encompasses an embedded C++ stack utilizing FreeRTOS multiprocessing, TinyUSB descriptor generation, an isolated 802.11 b/g/n Wi-Fi Access Point (SoftAP), and a browser-based HTML5/CSS3 touch digitizer stored within internal LittleFS flash memory. High-overhead multimedia features—specifically video feed back-streaming and host audio interception—are strictly demarcated as out-of-scope to preserve sub-30ms transmission responsiveness and avoid host-side software installations.

Stakeholder & Academic Governance: This document is submitted for rigorous academic review by project supervisors Muwanguzi Mark Ntume and Chunling Du, internal academic moderators, and external examiners within the Faculty of Information and Communication Technology at Tshwane University of Technology (TUT), fulfilling curriculum evaluation benchmarks for the National Diploma in Computer Systems Engineering.

2. SYSTEMS OVERVIEW

The system operates as an autonomous, agentless hardware dongle that establishes a responsive human-interface bridge between a mobile smartphone and a target host computer. When plugged directly into a host USB Type-A or Type-C receptacle, the ESP32-S3 hardware natively enumerates as a standard USB Composite Human Interface Device (HID), exposing integrated keyboard and mouse collections that require zero host-side drivers or administrator privileges.

Concurrently, the gateway initializes an isolated, high-speed 2.4 GHz SoftAP network (SSID: ESP32-Gateway). When an operator associates their smartphone with this local network and navigates to the default gateway address (192.168.4.1), an asynchronous embedded HTTP server delivers a lightweight, zero-dependency HTML5 mobile trackpad interface directly from flash memory into the mobile browser.

Upon initialization, the mobile client opens a persistent full-duplex WebSocket channel over TCP port 80. Real-time touch coordinates, tap events, gestures, and keystrokes captured on the phone's capacitive screen are serialized into compact JSON packets and streamed to the gateway. The microcontroller's firmware parses these packets across a FreeRTOS inter-core queue, translates them into compliant USB HID report buffers, and injects them into the physical USB endpoint FIFO with guaranteed sub-30ms latency, enabling fluid cursor manipulation and text entry while bypassing host OS security restrictions.

3. DESIGN CONSIDERATIONS

  • Sub-30ms End-to-End Latency Target: Fluid cursor movement requires tactile response latencies below 50ms to prevent perceptible operator overshooting. Total system latency (Ttotal = Ttouch_sample + Tws_transmit + Tesp_decode + Tusb_poll) is engineered to consistently remain below 30ms through 60Hz digitizer sampling, asynchronous non-blocking sockets, zero-copy memory dispatching, and a 125Hz USB polling rate.
  • Zero-Driver Universal Compatibility: Strict compliance with the USB Implementers Forum HID Class Specification v1.11 ensures that the hardware gateway is recognized out-of-the-box by Windows 10/11, macOS, and standard Linux kernel distributions without administrative privileges, driver installers, or background helper daemons.
  • Air-Gap Integrity & Physical Radio Cutoff: In high-security IT rooms and financial server enclosures, foreign networking equipment is strictly restricted. The gateway enforces air-gap isolation by operating strictly in local SoftAP mode without WAN uplinks or bridge interfaces. To provide emergency physical security, an active-low tactile push-button tied to hardware GPIO 4 triggers an immediate interrupt that terminates RF broadcasting within 2ms.
  • Power and Thermal Budgeting: The hardware operates solely from the host 5V VBUS rail (5V ± 5%, maximum 500mA according to USB 2.0 specifications). Measured peak power consumption remains below 280mA (1.4W) under continuous Wi-Fi packet transmission and active USB enumeration, allowing safe passive heat dissipation inside a compact 3D-printed enclosure.

5. GOALS AND GUIDELINES

  • Operational Simplicity & Zero-Dependency Delivery (KISS Principle): The mobile web application is engineered entirely with zero-framework vanilla JavaScript and pure CSS3. Bypassing heavy client-side frameworks (such as React or Angular) guarantees instant load times (<100ms) directly from the ESP32-S3 LittleFS partition on any mobile browser without internet access or CDN caching.
  • Throughput Maximization vs. Deterministic Memory Limits: Real-time responsivity takes priority over speculative memory caching. The embedded firmware employs asymmetric task pinning across FreeRTOS cores (Core 0 dedicated to wireless socket processing, Core 1 dedicated to USB HID formatting) and relies on fixed-size circular ring buffers, preventing heap fragmentation and ensuring microsecond-level timing predictability.
  • Ergonomic Tactile Parity with Physical Touchpads: The web touch engine faithfully mirrors the physical sensation of modern laptop hardware. It incorporates a non-linear velocity scaling algorithm (V = α · (ΔD)1.2) that smooths minor physiological tremors during slow precision tracking while enabling rapid cross-display navigation during flick gestures, complemented by dedicated multi-touch scrolling and tap gestures.

6. DEVELOPMENT METHODS

Iterative Hardware-Firmware Co-Design Paradigm: Development is guided by an Agile milestone methodology combining rapid electronic breadboard prototyping with continuous firmware module integration. Hardware differential routing, RTOS task synchronization, and client-side gesture capture are validated concurrently at each design sprint to de-risk physical USB bus timing dependencies early.

Formal and Published Engineering Standards Adopted:

  • IEEE 1016 Systems Design Documentation Standard: Governs the structural decomposition, subsystem abstractions, component attributes, and functional flow models documented throughout this project.
  • USB-IF HID Specification v1.11: Establishes the authoritative binary descriptor formats and report buffer structures required for driverless operating system enumeration.
  • IETF RFC 6455 WebSocket Protocol: Specifies the full-duplex, low-framing-overhead transport standard governing bidirectional streaming between browser and microcontroller over TCP port 80.

Comparative Evaluation of Alternatives Considered:

  • Traditional Waterfall Lifecycle: Rejected due to rigid stage barriers, which introduce severe risk when attempting to synchronize real-time Wi-Fi packet throughput with physical USB differential signaling.
  • Software Remote Desktop Solutions (VNC, RDP, TeamViewer): Evaluated and rejected because they mandate host-side software installation, network firewall modifications, and elevated user rights—violating core project constraints.
  • Bluetooth Classic HID Mode: Considered but discarded due to OS-dependent pairing dialogues, high connection negotiation latency, and inconsistent report delivery rates compared to dedicated local 802.11 WebSockets.

7. ARCHITECTURAL STRATEGIES

  • Toolchain & Language Architecture: C++ utilizing the Arduino ESP32 runtime and ESP-IDF hardware abstraction layer was selected over MicroPython to attain deterministic execution speed, direct hardware interrupt vector management, and native FreeRTOS multiprocessing primitives.
  • Software Component Reuse: High-performance, community-validated open-source libraries are integrated: Adafruit_TinyUSB for USB descriptor generation, ESPAsyncWebServer and AsyncTCP for non-blocking asynchronous socket servicing, and ArduinoJson for zero-allocation stream parsing.
  • Hardware Extensibility Strategy: The physical circuit layout reserves dedicated SPI bus lines (GPIO 10, 11, 12, 13) for an optional MicroSD card daughterboard, enabling future offline storage and execution of Duckyscript-compatible administrative macro routines.
  • Client Interaction Model: A full-screen zero-dependency HTML5 canvas intercepts W3C Touch Events Level 2 (touchstart, touchmove, touchend), translating touch displacement deltas into relative cursor movement vectors with dynamic acceleration curves.
  • Physical Hardware Interfacing: Direct differential routing maps native USB D+ and D- traces directly to ESP32-S3 GPIO 20 and 19 using the internal Full-Speed USB OTG PHY, eliminating external USB-UART bridge chips (such as CH340 or CP2102) and reducing propagation delays.
  • Fault Tolerance & Link Recovery: An embedded Hardware Watchdog Timer (WDT) set to a 3-second timeout reboots the microcontroller upon unexpected thread lockups; WebSocket heartbeat pings (5s interval) detect broken wireless sessions; and USB bus reset ISRs manage host re-enumeration.
  • Dynamic Memory Protection Policies: Statically pre-allocated circular ring buffers (depth: 32 report structures) absorb rapid input bursts without dynamic heap allocations, while LittleFS partitions stream static web assets directly into client browser caches.
  • Isolated Network Architecture: An isolated 802.11 b/g/n SoftAP (192.168.4.1) with captive DNS routing handles local client connections, remaining strictly detached from wider area networks to enforce hardware-level air-gap security.
  • Multiprocessing Task Allocation: Dual-core asymmetric processing under FreeRTOS: Core 0 executes the Wi-Fi MAC, LwIP TCP/IP stack, and WebSocket parser; Core 1 formats HID reports and drives hardware GPIOs. Tasks communicate via lock-free atomic queues (xQueueSendFromISR, xQueueReceive).
  • Hardware Emergency RF Termination: An active-low hardware push-button tied to GPIO 4 triggers a high-priority interrupt executing esp_wifi_stop(), terminating RF broadcasting at the physical layer within 2ms.

8. SYSTEM ARCHITECTURE

The system architecture is organized into three decoupled operational tiers, isolating client gesture capture from deterministic physical USB hardware dispatching:

|        LAYER 1: MOBILE CLIENT      |      |      LAYER 2: ESP32-S3 GATEWAY     |      |        LAYER 3: TARGET PC          |
|                                    |      |                                    |      |                                    |
|   HTML5 Touch Canvas (60Hz)        |      |   AsyncWebServer & LwIP (Core 0)   |      |   Native OS HID Driver             |
|   Gesture & Velocity Math Engine   | ===> |   Packet Parser & Atomic Queue     | ===> |   Mouse Cursor & Keystroke         |
|   WebSocket Client Serializer      |      |   TinyUSB Composite HID (Core 1)   |      |   Ingestion                        |
|                                    |      |                                    |      |                                    |

            [Wi-Fi SoftAP / WS]                               [USB OTG D+ / D-]

Rationale for Decomposition: Partitioning network socket ingestion on Core 0 from hardware USB interrupt endpoint servicing on Core 1 ensures that wireless frame retransmissions, client beacon intervals, or radio interference never introduce timing jitter into the physical 125Hz USB polling loop, guaranteeing stable sub-30ms user response.

Subsystem Architecture

  1. Network & Communication Subsystem: Manages 802.11b/g/n SoftAP broadcasting (SSID: ESP32-Gateway), assigns local IP leases via DHCP, and hosts an asynchronous HTTP and WebSocket server listening on port 80.
  2. Touch & Input Processing Subsystem: Executes client-side inside the mobile web browser. Captures raw touch vectors, filters low-frequency tremor through a deadband threshold, and applies non-linear acceleration curves to displacement deltas.
  3. USB HID Translation Subsystem: Deserializes JSON command payloads and generates standard USB HID reports, injecting mouse data (buttons, ΔX, ΔY, scroll) and keyboard reports (modifier flags, keycodes 1–6) into the USB endpoint FIFO.
  4. Hardware Safety & Power Subsystem: Regulates the host 5V USB bus line to 3.3V, monitors the active-low hardware kill-switch interrupt, and drives status LEDs indicating Wi-Fi client association and USB transmission activity.

3. SOFTWARE SUMMARY

The system translates mobile capacitive multi-touch inputs, virtual keyboard entries, and administrative macros into standard USB HID reports.

  • Sub-30ms Tactile Pointer Tracking: Employs non-linear velocity scaling (V = α · (ΔD)1.2) damping hand tremors while enabling rapid flick travel.

4. ACCESS TO THE SOFTWARE

4.1 Installation & Startup

  1. Hardware Insertion: Plug the ESP32-S3 dongle into an available USB Type-A or Type-C port on the target machine. Within 2–3 seconds, the target OS registers the device as a standard keyboard/mouse (Amber LED turns solid).
  2. Network Association: Open phone Wi-Fi settings and connect to ESP32-Gateway (Passphrase: Password123).
  3. Launch App: Open the Hardware Gateway app on your smartphone. The app automatically tests the WebSocket connection to ws://192.168.4.1/ws and UDP discovery on port 8765. Verify the green status pills (ESP32: Connected).

4.2 Description of Inputs & Outputs

Inputs are formatted as compact UTF-8 JSON text frames across WebSockets:

{"t":"m", "dx":14, "dy":-8}                 // Relative pointer delta
{"t":"b", "btn":1, "state":1}               // Left button down
{"t":"k", "key":"A", "mod":2}               // Injected key 'A' (Shift modifier)
{"t":"cmd", "id":"TASK_MGR"}                // Macro shortcut

Outputs: 4-byte standard USB HID mouse reports, 8-byte standard USB HID keyboard reports, hardware status LEDs, and real-time screen display with Windows Aero cursor overlay.

4.3 Recovery Procedures

Symptom Root Cause Corrective Action
Pill displays ESP32: Offline Wi-Fi association dropped. Reconnect to ESP32-Gateway in phone settings. Confirm dongle power.
Host cursor does not move Port lacks data lines. Ensure dongle is inserted into a functional data-capable USB OTG port.
Pill displays Screen: Offline Host streamer daemon stopped. Launch HardwareGatewayStream.py on PC. Allow port 8765 in firewall.
Cursor sensitivity miscalibrated Software slider setting. Tap Settings (Gear) icon; adjust sensitivity between 0.4× and 2.5×.
Wi-Fi drops and cannot reconnect Hardware kill-switch pressed. Power cycle hardware gateway (unplug and re-insert USB) to re-enable Wi-Fi.

4.4 Stopping & Emergency Severance

  • Normal Disconnection: Close mobile application or disconnect Wi-Fi. The gateway enters low-power standby mode.
  • Emergency RF Termination: Press the tactile push-button on the enclosure. The active-low hardware interrupt executes esp_wifi_stop() in <2 ms, terminating all RF broadcasting instantly while maintaining the physical USB link.
  • Full Powerdown: Unplug the ESP32-S3 dongle from the host PC USB port.

6. QUERY PROCEDURES

The system exchanges asynchronous query/response datagrams over UDP and WebSockets:

  • UDP Auto-Discovery: The mobile client broadcasts HW_GATEWAY_DISCOVERY_PROBE on UDP port 8765 every 5 seconds. The host daemon responds with its server hostname and IP, enabling zero-configuration auto-connection.
  • Preset Switching: The Settings sheet allows one-tap switching between network environments:
    • Campus Wi-Fi: Connects to host at 10.2.39.171:8765.
    • ESP32 SoftAP: Connects to host at 192.168.4.3:8765.
    • USB Tether: Connects to host via loopback at 127.0.0.1:8765.
